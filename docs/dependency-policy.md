# Политика зависимостей

Три контура, каждый со своей ролью. Ни один из них не заменяет остальные.

| Контур | Что гарантирует | Где |
|---|---|---|
| **Lock-контракт** | каждый прямой пакет покрыт ровно одним `==`-пином, без URL и платформенных маркеров | `tools/check_requirements_lock.py`, `services/runtime_dependency_lock.py` |
| **Аудит уязвимостей** | в разрешённом lock нет известных CVE (кроме письменно одобренных исключений) | `tools/audit_requirements_lock.py` |
| **Автообновление** | отставание не остаётся невидимым — приходят PR | `.github/dependabot.yml` |

## Порядок изменения пина

1. Правка floor'а в `requirements.txt` / `requirements-dev.txt` (там же — верхняя граница).
2. Правка точного пина в `requirements-lock.txt`.
3. `python tools/check_requirements_lock.py` — контракт lock'а.
4. `python tools/audit_requirements_lock.py` — известные уязвимости.
5. `python -m pytest` — полный прогон.

CI делает шаги 3–4 в блокирующей джобе `dependency-audit`; без неё красный шлюз
`Required PR Gate` merge не пропустит (ruleset `Protect main`, strict).

## Политика аудита: `resolved-lock-zero-known-vulnerabilities-v1`

- Уязвимость **с опубликованным фиксом** — всегда падение сборки. Обходного пути нет.
- Уязвимость **без фикса** можно внести в `ALLOWED_ADVISORIES` только с тремя полями:
  пакет, письменная причина (почему риск приемлем в нашем сценарии использования) и
  **дата пересмотра**. После этой даты исключение снова блокирует сборку.
- Запись, которая больше не встречается в отчёте, **тоже валит сборку**: устаревшее
  исключение — это скрытая дыра в будущем.
- Аудит требует `pip-audit` в `PATH` (CI ставит зафиксированную версию `2.10.1`);
  отсутствие инструмента — это падение, а не «пропуск проверки».

Текущее состояние: единственное исключение — `pdfkit 1.0.0` (`PYSEC-2026-2860`,
фикса у апстрима нет), пересмотр до **2027-01-31**.

## Dependabot

- `pip`, каталог `/`: одна запись, ежедневно, сгруппировано. Первая группа —
  `youtube-downloader` (`yt-dlp` + `yt-dlp-ejs`): поломка экстрактора YouTube =
  продовый инцидент, ждать неделю нельзя. Остальное — группы `pip-minor-and-patch`
  и `pip-major`, которые эту пару **исключают** (`exclude-patterns`), чтобы по одному
  пакету не открывались конкурирующие PR.
  Двух отдельных pip-записей быть не может: Dependabot отклоняет конфиг с
  повторяющейся комбинацией `(package-ecosystem, directory, target-branch)`
  (`.github/dependabot.yml` проверяется GitHub'ом на каждом PR — «overlapping
  directories» валит check). Поэтому групповой порядок и `exclude-patterns`
  зафиксированы тестами, а не только комментарием.
- `npm`, каталог `/vot_helper`: еженедельно, группа `@vot.js/*`.
- `github-actions`: еженедельно, одна группа.

Все PR проходят тот же шлюз. Обновление мажора — отдельный PR: ревью и полный прогон
обязательны, группы minor/patch нужны только чтобы не тонуть в рутине.

## Python floor

Проект поддерживает 3.11–3.13 (CI гоняет все три). Часть аудио-стека
(`numpy 2.5`, `av 19`, `huggingface-hub 2`, `websockets 17`, `onnxruntime 1.31`)
требует **≥3.12**. Пока floor не поднят, эти мажоры осознанно остаются на старых
версиях — это записанное решение, а не забытый пин. Поднятие floor'а до 3.12 —
отдельная задача с проверкой на Windows-рантайме (`Start Bot.bat`, CUDA/VoxCPM2).
