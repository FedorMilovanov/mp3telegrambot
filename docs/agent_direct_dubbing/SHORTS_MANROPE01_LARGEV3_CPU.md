# Обязательный профиль SHORTOREZ / Manrope 01 / Large-v3 на CPU

Применяется к **локальному операторскому производству новых вертикальных русскоязычных Shorts**, когда выбран наш профиль **«Manrope 01»**. Не меняет глобально режимы Telegram-бота, существующие рендеры, провайдерные права, LiveDub или Factory без явного задания. Сведения по SHORTOREZ, crop и границам из [CLIPS_SHORTS_AND_HANDOFF.md](CLIPS_SHORTS_AND_HANDOFF.md) и текущего `services/shortorez_shot_plan.py` остаются обязательными.

## Важное: на этом ПК CUDA для Whisper не используем

- Стандарт для фактически звучащей русской речи: **`faster-whisper large-v3` на CPU, INT8**, с `language="ru"` и `word_timestamps=True`. Режимы `small`, `medium`, `large-v3-turbo` и бесконтрольный fallback **запрещены для финальных Shorts Manrope 01**.
- Прямой локальный операторский путь:
  ```python
  WhisperModel("large-v3", device="cpu", compute_type="int8", local_files_only=True)
  ```
  Не делать `torch.cuda.is_available()` или загрузку `WhisperModel(..., device="cuda")` как предварительный тест на этом ПК: CUDA/CTranslate2 в проверенном сценарии аварийно завершались; CPU работал.
- Для **Shorts Factory MAX** уже обязательна именно `large-v3` (см. `services/shorts_transcription.py::factory_subtitle_profile` и `docs/shorts_factory_max.md`). **На этом ПК** фиксировать `WHISPER_FORCE_CPU=1`, `WHISPER_DEVICE=cpu`, `SHORTS_FACTORY_WHISPER_MODEL=large-v3` в локальной конфигурации или командном окружении. Пример уже есть в `config/shorts_factory.env.example`. Не менять чужой production `.env` автоматически и не предполагать, что пример `.env.example` активирован.
- Если модель/CPU-окружение недоступны — **HOLD**, не снижать модель и не объявлять прошедшей проверки на основе лишь успешно записанного WAV/MP4.

## Выбранное оформление (не вариация для экспериментов)

- **Manrope 01:** статический **Manrope ExtraBold 800**, при генерации ASS для Q&A №54 face `Manrope Q54`. 1080×1920 9:16 H.264/AAC `yuv420p`.
- Слова подсвечиваются по одному: **активное #FFE17D**, неактивное **#FFFAF1**, отдельные подтверждённые богословские термины — **#F26F7E**, контур **#101821**. Оригинальные размеры Q&A №54: **Body x=540 y=1426**, размер 91 px с необходимым сжатием до 54 px, не более 2 строк и около 805 px ширины; титулы x=91 y=166/231/320. Не переносить координаты слепо на другой размер кадра.
- Кикер обязан объяснять **кто говорит и откуда фрагмент**: автор + номер/название исходного Q&A, ниже тема. Одинокое «Вопрос 02 из 17» неприемлемо для зрителя, которому ролик попался случайно.
- **Длинные 16:9 мастер-ролики не получают вшитые субтитры по умолчанию в этом заказе.** Не удалять дополнительные внешние SRT, если они нужны отдельным workflow; не вшивать их без прямого указания.
- Не коммитить `.ttf` и прочие приватные медиа-артефакты. Манроповский статический face загружается из разрешённых локальных ресурсов; оформление финального MP4 проверить по его пикселям.

## Гейты, без которых агент не вправе сказать «под нуль»

1. Извлекать речь **из реально используемой дорожки**. Хранить исходный `large-v3` JSON и *отдельно* все редакторские замены `before/after/time/reason/listened`. Контекстные грамматические правки не объявлять результатом модели; сверять смысл и Писание на слух.
2. Перед рендером **слушать вход и выход с контекстом 3–8 сек**, убедиться, что не зацеплена предыдущая фраза, не съедена первая фонема и не пропущено завершение мысли. Тишина или ASR/VAD сами по себе не доказывают границу; Q&A требуют определения каждого отдельного вопроса.
3. Проверять **итоговый файл ASS** после округления до сотых секунды: все нижние `Dialogue: ...,Body,...` строго `start < end`, и `end <= next_start`. Не допускать двух одновременно видимых нижних фраз. Верхние титры на отдельном слое не считаются конфликтом. **Удержание одного активного слова >3,0 с** — редакционный QA/HOLD: проверить паузу и синхронизацию, а не растягивать караоке до следующей реплики.
4. По каждому **исходному монтажному плану** проверить фиксированный 9:16 crop, видимость лица и отсутствие виртуального слежения/blur. Сам `ffprobe` по 1080×1920 не доказывает качество кадра.
5. После рендера `ffprobe` **точного** MP4, декодировать начало/конец, проверить H.264/AAC, `yuv420p`, длительность ≤180 с и SHA-256. **Нет moov atom / файл заполнен NUL / FFprobe отказал** — удалить только явно созданный временный неудачный вывод или изолировать; перерендерить безопасно, не трогая проверенные старые файлы.
6. `TECH_QA_PASS`, `LISTENING_APPROVED`, `RIGHTS_APPROVED`, `PUBLISH_AUTHORIZED` — **разные** состояния. Нет ручного полного прослушивания — нет `LISTENING_APPROVED` даже при нуле наложений.
7. Отдать **готовый файл/рабочую проверенную галерею**, не очередную инструкцию по сборке. Локальный сервер `127.0.0.1` ненадёжен как единственная выдача: дополнительно сохранять офлайн-HTML с прямыми относительными ссылками на MP4 или открываемую папку.

**Эпизод-доказательство:** в Q&A №54 `small` искажала богословские термины, `large-v3` дала лучшие слова; ручные проверки понадобились для падежей и границ. Исправили наложения ASS, одну секунду предыдущего ответа, крупный план зрителя и файл Q05 без `moov`. Этот случай не позволяет объявлять другие ролики автоматически вычитанными.

Результат: **`TECH_QA_PASS` = техническая готовность, не публикация.** Отдельные исторические release-гейты и права остаются в силе.

## Пауза без самовольного перехода подсветки (`BodyHold`)

После проверки реальной речи запрещено красить следующее слово **раньше его произнесения** только потому, что Whisper ошибочно растянул предыдущее слово до очередного таймкода.

- Для верифицированного произнесённого слова использовать `Body` с активным янтарным цветом. Если одно активное слово длится **дольше 3,00 с**, это `SUBTITLE_TIMING_HOLD`, а не автоматическое одобрение: контекст Large-v3 не заменяет слуховую проверку.
- Если между словами есть подтверждённая пауза, сохранить **тот же видимый текст** через отдельный `BodyHold` с тем же стилем `Manrope Q54`, но **без активного янтарного цвета, повторного fade и изменения текста**. Следующее `Body` — только с подтверждённого момента нового слова. Это не «перескакивание» к новой фразе.
- Проверять общую шкалу `Body + BodyHold`: `start < end`, ни одного пересечения, шрифт/цвет/поле совпадают, длительное `BodyHold` не маскирует бесконечно зависший титр. Верхние `Title/Kicker` остаются отдельными слоями.
- Нельзя механически делить длинное слово на произвольные 1,5 секунды. В Q&A №54 Q01/Q12/Q15 повторный `large-v3` показал **ошибочное раннее появление слов**; Q11 остался спорным. Для Q15 модель дополнительно дала «также» с низкой вероятностью ~0,23 — **не вставлять такую гипотезу без реального прослушивания**.
- Перед окончательным релизом предъявить **парные мини-MP4 до/после со звуком**, проверить фактический ASS после округления, готовый MP4/FFprobe/SHA и сохранить отдельный редакторский журнал. **Технический PASS не даёт разрешения на публикацию.**

Детерминированный `BodyHold`-валидатор и регрессионные тесты находятся в `video-channel-manager/scripts/validate_manrope01_review.py`; при производстве по этому профилю применять именно актуальную версию из `main`, а не локальную копию скрипта без проверки SHA.
