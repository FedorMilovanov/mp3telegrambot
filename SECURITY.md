# Безопасность

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватный security advisory:

`https://github.com/FedorMilovanov/mp3telegrambot/security/advisories/new`

В сообщении полезно указать: затронутый модуль, шаги воспроизведения, влияние
(утечка секрета, выполнение кода, отказ в обслуживании) и версию
(`mp3bot --version`).

Ответ ожидайте в течение недели. Проект личный, поэтому сроки — «как можно
быстрее», без SLA.

## Поддерживаемые версии

Поддерживается только текущий `main`. Отдельных LTS-веток нет: исправления
выходят вперёд, а не бэкпортируются.

## Что считается секретом

| Категория | Примеры переменных | Где живёт |
|---|---|---|
| Telegram | `BOT_TOKEN`, `TELEGRAM_API_HASH`, `TELEGRAM_API_ID` | `.env` (не в git) |
| Gemini | `GEMINI_API_KEY`, `GEMINI_API_KEY_2..4` | `.env` |
| Yandex | `YANDEX_OAUTH_TOKEN` | `.env` |
| VK | `VK_TOKEN` | `.env` |
| YouTube | cookies / PO-token рантайм | `cookies.txt`, каталог рантайма (в `.gitignore`) |

`*.env`, `.env.*`, `cookies.txt`, `*.db` и `*.log` исключены в `.gitignore`.
`.env.example` содержит **только заглушки** — настоящий ключ там тоже утечка.

## Что уже сделано против утечек

| Механизм | Где | Что проверяет |
|---|---|---|
| `gitleaks` | `.github/workflows/secret-scan.yml` | полная история git на push, на каждый PR и weekly |
| `.gitleaks.toml` | корень | узкий allowlist известных заглушек; каталоги целиком не разрешены |
| `CodeQL` | `.github/workflows/codeql.yml` | SAST для Python и JS (`security-extended`) |
| Secret scanning + push protection | настройки репозитория GitHub | блокирует пуш с ключом известного формата |
| `pre-commit` | `.pre-commit-config.yaml` | локальные проверки до пуша |
| `tools/verify_repo.py` | `pre-push` и CI | генерируемые артефакты, тесты, ruff |

Локальная проверка перед коммитом (если установлен бинарь):

```bash
gitleaks protect --staged --redact
```

## Правила для кода

- секреты читаются **только** из окружения (`os.getenv`), никогда не попадают в
  код, тесты или документацию — даже как «пример настоящего ключа»;
- логирование: значения токенов не печатаются; допустима только форма
  «present / absent» (например, `services/search.py`);
- тесты используют фиктивные ключи правильного формата и добавляют их в
  `.gitleaks.toml` **по одному литералу**, а не путём целиком;
- внешние входы (URL из сообщений, имена файлов, HTML страниц) считаются
  недоверенными: `subprocess` — только списком аргументов, без `shell=True`;
- сетевые вызовы — всегда с таймаутом (проверено: 16/16 вызовов `requests`).

## Ограничения deployment'а, которые влияют на риск

- бот обслуживает одного владельца, поэтому многопользовательской авторизации нет;
- Local Bot API и модель работают на той же машине: компрометация хоста = компрометация
  всех токенов, ротация описана в `README.md`;
- Gemini используется на бесплатной квоте: при исчерпании бот ждёт, а не
  переключается на платный ключ ([`docs/dependency-policy.md`](docs/dependency-policy.md)).

## Что делать при утечке

1. Отозвать ключ у провайдера (Telegram → BotFather, Gemini → AI Studio, Yandex → OAuth).
2. Заменить значение в `.env` и перезапустить бота.
3. Проверить, что секрет не попал в историю: `gitleaks detect --log-opts=--all`.
4. Если попал — переписать историю и **всё равно** считать ключ скомпрометированным.
